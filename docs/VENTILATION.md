# 연속 환기·얼굴 승인 운영 안내

2026-10-15 바탕화면 요청 파일을 반영한 `ventilation`, 정책 버전 6입니다. 관리자 화면은 한글, LCD 2004A 상태는 영어로 표시합니다. D10은 배기팬 역할의 연속 회전 서보입니다. IR은 사용하지 않습니다.

## 자동 제어

| 조건 | RGB LED | D9 | D10 | LCD | 설정 조작 |
|---|---|---|---|---|---|
| 정상 | 초록 | 0° | 저속 연속 | NORMAL | 관리자 PIN |
| 온도 27°C 이상~28°C 미만 또는 가스 경고 | 주황 | 90° | 고속 연속 | CAUTION | 관리자 PIN |
| 온도 28°C 이상 또는 온도 자동 정지 유지 중 | 빨강 | 0° | 정지 | TEMP AUTO STOP | 재가동·수동 개폐 대기 |
| 미승인만 | 초록 ↔ 빨강, 각 0.4초 | 0° | 저속 유지 | UNAUTHORIZED | 잠금 |
| 온도 주의·가스 경고 + 미승인 | 주황 ↔ 빨강 | 90° | 고속 유지 | DANGER | 잠금 |
| 온도 자동 정지 + 미승인 | 빨강 유지 | 0° | 정지 | TEMP AUTO STOP | 잠금 유지 |
| 긴급 정지 | 꺼짐 | 0° | 정지 | STOPPED | 자동 제어로 복귀 |
| 장치 오류 | 오류 표시 | 알려진 환경 경고 시 90°, 그 외 마지막 위치 유지 | 정지 | DEVICE ERROR | 잠금 |

**미승인 인원만 감지되면 부저는 무음**이며 LED·LCD 표시, 설정 잠금과 서보 제어는 유지합니다. 온도 자동 정지 중에는 부저를 끕니다. 그 외 환경 경고와 장치 오류의 경고음은 유지합니다. 두 조건이 겹치면 환경 경고음을 사용하며 출입 잠금은 유지합니다. 긴급 정지는 환경 경고보다 우선합니다. 표의 각도는 자동 모드 기준이며 관리자 수동 개폐는 별도입니다. 센서·카메라 감시는 정지 중에도 계속됩니다.

온도 **27°C 이상 또는 MQ-9 ADC 원시값 250 이상**에서 환경 경고가 켜집니다. **28°C 이상을 측정하면 즉시 온도 자동 정지**합니다. D10 정지·D9 0°·부저 꺼짐이며 빨간 LED와 센서·카메라 감시는 유지합니다. 온도가 내려가도 **27°C 미만의 유효한 측정이 5초 이상 유지**될 때까지 빨강과 정지를 유지합니다. 다시 27°C 이상이 되거나 데이터가 잘못되거나 끊기면 복귀 확인 시간을 다시 셉니다. DHT11은 2.5초마다 측정하므로 실제 복귀는 다음 측정·통신 시점에 반영됩니다.

온도 자동 정지만 발생한 경우에는 PIN 없이 자동 운전을 재개합니다. 사용자가 누른 긴급 정지, 장치 오류로 유지된 정지, 감독 프로세스 재시작 정지는 자동으로 해제하지 않습니다. 미승인 표시의 빨강 점멸만으로 온도 자동 정지를 걸지는 않으며, 온도 복귀 후에도 미승인 잠금은 유지합니다. 가스 경고가 남으면 기존 고속 환기로 돌아갑니다. 가스 경고의 250/210 기준과 해제 후 2초 대기는 유지합니다. 원시값은 보정된 ppm 농도가 아니며 이 기준은 교육용 시연값입니다.

## 실행과 관리자 조작

```bash
cd '/home/moble/2.5th project'
DISPLAY=:0 bash run_ventilation.sh
# 장치 미구동 시뮬레이션
DISPLAY=:0 bash run_ventilation.sh --simulate --scenario warm_intrusion
# 시리얼 출력 없이 카메라·얼굴 등록만 사용
DISPLAY=:0 bash run_ventilation.sh --camera-only
```

바탕화면 **Moble 연속 환기**도 같은 설정을 실행합니다. 온도·습도·가스 숫자와 최근 60초 그래프를 표시하고, 오래되거나 잘못된 센서 데이터는 수신 대기와 그래프의 끊김으로 표시합니다. 화면에서 IR과 팬 운전 재개 버튼을 제거했습니다.

- **긴급 정지:** PIN 없이 D10 정지, D9 0°, LED·부저 꺼짐. LCD는 STOPPED입니다.
- **유입구 열기 / 닫기:** 관리자 PIN을 확인하고 D9를 90° / 0°로 유지합니다. 미승인·장치 오류·온도 자동 정지에서는 잠깁니다.
- **자동 제어:** 수동 선택과 긴급 정지를 해제하고 센서 기준의 각도·팬 속도로 돌아갑니다. 오류·미승인·온도 자동 정지 상태에서는 강제로 복귀할 수 없습니다. 버튼 선택 표시도 자동으로 바뀝니다.
- **경보 해제:** 항상 누를 수 있으며 관리자 PIN을 확인합니다. 현재 원인의 경보음을 해제합니다. 원인이 남아 있으면 상태 표시와 설정 잠금은 유지하고, 새 경보 원인이 생기면 다시 소리를 냅니다. 빈 구역이 확인됐을 때는 남아 있는 미승인 경보도 해제합니다.
- **승인자 얼굴 등록 / 등록자 관리:** PIN 확인 후 등록·삭제합니다. 등록 관리와 긴급 정지는 미승인 잠금 중에도 접근할 수 있습니다.

처음 연결 상태가 정상으로 확인되면 팬은 자동으로 운전합니다. 동작 중 센서·통신·카메라 오류가 발생하거나 감독 프로세스가 충돌 후 복구한 경우에는 팬 정지가 유지됩니다. 오류가 해제된 뒤 **자동 제어**로 재개합니다. 사용자가 프로그램을 완전히 닫고 새로 실행하면 다시 정상 상태 확인 후 자동 운전합니다.

## 얼굴 등록과 자동 승인

1. 실제 운영 화면에서 **승인자 얼굴 등록**을 누르고 관리자 PIN을 입력합니다.
2. 이름을 입력하고, 카메라에 한 명만 보이도록 정면을 바라봅니다. 얼굴이 너무 작거나 흐리면 가까이 이동합니다.
3. 30초 안에 품질 조건을 충족하는 얼굴 특징 8개를 수집합니다. 등록 완료 표시를 확인합니다.
4. 이후 등록된 얼굴이 연속 3회 확인되면 자동 승인합니다. 프로그램 재실행 뒤에도 등록 정보가 유지됩니다.
5. **등록자 관리 → 선택한 등록자 삭제**로 삭제합니다. 삭제 즉시 기존 승인과 카메라 판정을 취소하고 다시 확인합니다.

사람 검출은 YOLOv5n, 얼굴 검출은 YuNet, 얼굴 특징은 SFace를 TensorRT FP16 GPU로 실행합니다. **카메라에 가장 가까운 것으로 추정한 한 명만 출입 판정**합니다. 전체 감지 인원수는 따로 표시하고, 판정 대상에게만 테두리를 표시합니다. 등록 여부와 무관하게 대상을 먼저 선택한 뒤 그 사람의 얼굴을 확인합니다.

| 카메라 상황 | 출입 판정 |
|---|---|
| 승인자가 앞, 미승인자가 뒤 | 앞의 승인자 확인 후 자동 승인, 미승인 경보 없음 |
| 미승인자가 앞, 승인자가 뒤 | 미승인 경보·설정 잠금 |
| 앞사람 얼굴이 보이지 않거나 너무 작고 흐림 | 미승인, 뒤쪽 승인자로 대신 승인하지 않음 |
| 가까운 승인자가 확인됐지만 온도·가스 기준 초과 | 출입은 승인, 주의·가스 경고는 고속 환기, 온도 위험은 자동 정지 |

거리는 직접 측정하지 않습니다. 얼굴이 보이면 얼굴 상자의 가로·세로 기하평균, 얼굴이 없으면 몸 상자의 `max(가로/3, 세로/7)`로 화면상 크기를 비교합니다. 몸 크기 환산 계수는 이 시제품의 추정값이며 보정된 거리 공식이 아닙니다. [단안 카메라의 원근 투영](https://docs.opencv.org/4.5.5/d9/d0c/group__calib3d.html)에서 영상 크기는 실제 크기와 거리 모두에 영향을 받으므로, 체격·자세·가림·화면 잘림에 따라 순서가 다르게 추정될 수 있습니다. 사람이 겹치거나 검출되지 않으면 정확한 앞뒤 판정을 보장하지 않습니다.

가까운 등록 얼굴을 새 영상에서 연속 3회 확인하면 승인하고, 경보 상태의 정상 복귀에는 기존 2초 안정 시간을 적용합니다. 뒤쪽 인원수만 바뀌면 같은 앞사람의 승인은 유지합니다. 미승인자가 앞에 나타나거나 카메라 판정이 오래되면 승인을 취소합니다. 얼굴 등록은 계속 한 명씩 진행합니다. 사람이 떠난 뒤 남은 미승인 경보는 빈 구역 확인 후 경보 해제로 정리합니다.

등록 정보는 프로젝트의 `data/identities.json`에 이름과 특징값으로 저장합니다. 파일은 소유자만 읽고 쓸 수 있고 저장은 임시 파일 교체 방식입니다. 손상된 파일은 조용히 초기화하지 않고 오류를 표시합니다. 원본 얼굴 사진은 저장하지 않습니다. 등록자 파일과 관리자 PIN은 배포 ZIP에서 제외합니다. 기기를 이전할 때 등록 정보를 보존하려면 이 파일을 별도로 관리해야 합니다.

2D 얼굴 유사도 기반 시제품이며 사진·영상 위조를 판별하는 생체 감지 기능은 없습니다. 실제 사용자 등록 후 조명·거리·안경·각도에 따른 승인·거부 결과를 확인해야 합니다. 기존 production/bench 프로필의 30초 수동 승인 방식은 별도로 유지합니다.

## 카메라와 GPU

640×480 MJPEG, 캡처 요청 60fps, 화면 목표 30fps입니다. USB 재연결로 video0/video1 번호가 바뀌는 문제를 확인해, 현재 운영 설정은 `/dev/v4l/by-id/usb-Global_Shutter_Camera_Global_Shutter_Camera_01.00.00-video-index0`으로 같은 카메라를 지정합니다. 다른 카메라를 사용할 때는 `config/ventilation.json`의 `camera.device`를 해당 장치 경로로 변경합니다. 얼굴 분석을 추가한 실제 카메라 20초 검사에서는 영상 수신 약 29.61fps, 사람·얼굴 분석 약 12.12회/초, 분석 시간 중앙값 67.71ms였습니다. 이는 헤드리스 측정이며 실제 Tk 화면 표시 FPS와 구분합니다. 영상 아래에 실제 표시 FPS가 나옵니다. 미리보기가 움직여도 AI 판정이 오래되면 승인하지 않습니다.

모델 출처·고정 SHA256과 라이선스는 `models/face-sources.json`, `YUNET_LICENSE`, `SFACE_LICENSE`에 있습니다. 다른 Jetson/TensorRT 환경에서는 엔진을 다시 생성합니다.

```bash
python3 scripts/build_face_engines.py
```

## 펌웨어와 검증

```bash
bash scripts/compile_ventilation.sh
# 운영 화면을 닫은 뒤 업로드
.tools/arduino-cli --config-file .tools/arduino-cli.yaml upload \
  --fqbn arduino:avr:mega --port /dev/ttyUSB0 \
  --input-dir build/mega-ventilation firmware/mega_controller
python3 -m unittest discover -s tests -v
```

정책 버전 6은 호스트와 MCU가 함께 적용돼야 합니다. 기존 버전이면 프로필 검증에서 운전을 차단합니다. MCU는 같은 28°C 정지·27°C 미만 5초 복귀 규칙을 독립적으로 적용합니다. 온도 자동 정지가 아닐 때 환경 경고는 허가된 팬을 고속 전환합니다. 호스트 정지나 오류를 무시하고 팬을 재시작하지 않습니다. 유효 명령이 3초 없으면 정지합니다.

D10은 정지 1500µs, 저속 1600µs, 고속 1800µs입니다. D9는 0°/90°입니다. R26/G22/B24, 공통 음극·내장 저항 RGB 배선을 유지하며 Timer1 PWM으로 초록을 25% 섞어 주황을 만듭니다. Servo는 Timer5, 줄인 음량의 부저는 Timer3 compare B/C를 사용합니다. Timer1은 RGB용입니다. 서보 전원은 사용자 확인 외부 5V 2A·공통 GND입니다. 실제 회전수·각도 피드백 센서는 없습니다.

가까운 한 명 판정 변경의 자동 검증은 `artifacts/nearest-person-tests.log`에 있으며 **115개 테스트를 통과**했습니다. 승인자·미승인자 앞뒤 교체, 얼굴이 안 보이거나 흐린 앞사람, 전체 인원 변화, 환경 경고 유지, 설정 잠금과 카메라 초기화 복구를 검사합니다. `nearest-person-gui-check.log`와 `nearest-person-dashboard.png`는 실제 Tk 위젯을 사용하는 합성 화면 검사이며, `nearest-person-live.json`은 실행 중인 카메라·통신 관측입니다. 사용자는 실제 두 사람의 앞뒤 위치를 바꿨을 때 두 경우 모두 화면 판정이 정상임을 확인했습니다(`nearest-person-user-acceptance.json`). 이 시험은 긴급 정지 중 화면으로 확인했으며 사이렌 청취 시험은 포함하지 않습니다.

GPU가 처음 내놓은 판정이 이미 오래된 경우, 최초의 최신 판정이 도착할 때까지 기존 30초 초기화 유예를 유지합니다. 준비 중 오래된 영상으로 승인하지 않으며, 최신 판정 수신 후에는 기존 3초 감시 제한을 그대로 적용합니다. 이 변경은 첫 GPU 처리 지연 때문에 재초기화가 반복될 수 있는 문제를 보완합니다.

이전 개정의 `artifacts/admin-tests.log`는 당시 자동 검증, `admin-ui-check.log`는 Tk 위젯 검사, `admin-face-camera-check.json`은 GPU·카메라 검사, `admin-firmware-build.log`는 컴파일 기록입니다. 당시 다인원 승인 규칙은 현재의 가까운 한 명 정책으로 대체됐습니다. `admin-serial-result.json`과 `admin-live-result.json`은 당시 실물 시험 기록입니다. 현재 설치 상태는 `hardware-commissioning-status.json`을 따릅니다.

출력 순서 시험은 실제 서보·부저를 작동시킵니다. 운영 화면을 닫고 다음 명령으로 정상·미승인·환경·동시·음소거·긴급 정지·수동 개폐·자동 복귀를 확인합니다. 실제 가스나 열은 가하지 않습니다.

```bash
python3 scripts/ventilation_serial_check.py --run-actuators --report artifacts/admin-serial-result.json
```

## 부저 음량 조정 (2026-10-15)

사용자 요청으로 현재 ventilation 펌웨어의 부저 구동을 낮췄습니다. 17% 듀티 시험도 여전히 크다는 사용자 피드백을 받아 5%로 한 번 더 낮췄습니다. 기존 [Arduino tone()](https://docs.arduino.cc/language-reference/en/functions/advanced-io/tone/)의 50% 듀티 파형 대신 D28에서 **5% 듀티**로 구동합니다. 당시 1~2.4kHz 사이렌을 사용해 청취 확인했으며, 이후 미승인 무음 요청을 반영해 현재는 환경·오류의 1.8/2kHz 경고음만 출력합니다. 기본 주파수 성분의 이론적 전압 진폭은 기존의 약 16%입니다. 실제 음압이나 사람이 느끼는 크기가 정확히 절반이라는 의미는 아니며, 모듈 특성에 따라 청취 확인이 필요합니다. 사용자가 5% 설정의 시험 소리를 듣고 “이제 적당함”으로 확인했습니다. 실제 dB는 측정하지 않았습니다.

`hardware_config.h`의 `BUZZER_DUTY_PERCENT=5`로 설정합니다. 값의 단위는 펄스 듀티(1~50%)이며 사용자 체감 음량 백분율이 아닙니다. Timer3 CTC·분주 8을 사용하고, Servo가 선언하는 compare A 인터럽트는 활성화하지 않습니다. Timer3를 다른 용도로 함께 사용하지 않습니다. [ATmega2560 데이터시트](https://ww1.microchip.com/downloads/aemDocuments/documents/OTH/ProductDocuments/DataSheets/ATmega640-1280-1281-2560-2561-Datasheet-DS40002211A.pdf)의 16비트 타이머 CTC 동작을 따릅니다. 배선은 D28을 유지합니다.

정비 후 정지를 유지하며 프로그램을 열려면 `DISPLAY=:0 bash run_ventilation.sh --start-stopped`를 사용합니다. 이 옵션은 시작 시 긴급 정지를 적용하며, 관리자 PIN을 확인한 자동 제어로 복귀합니다. 부저 시험은 `python3 scripts/quiet_buzzer_check.py --play`로 3초 동안 수행하며, D10 OFF·D9 0°를 유지합니다. 운영 프로그램을 먼저 닫아야 합니다.

## 이전 변경 기록: 27°C 경고·미승인 무음 (정책 버전 4)

프로그램과 Mega 정책 버전 4에 온도 27°C 이상 경고, 25°C 미만 해제를 적용했습니다. 미승인만으로는 부저를 울리지 않으며 초록·빨강 점멸과 설정 잠금, D9 0°·D10 저속 동작을 유지합니다. 환경 경고가 겹치면 주황·빨강 점멸, 고속 환기와 환경 경고음이 동작합니다. 환경 경고가 해제되고 미승인만 남으면 다시 무음입니다.

`artifacts/temp27-silent-intrusion-tests.log`는 경계값·해제 지연·동시 경고·잠금과 실제 펌웨어 음 패턴 함수를 포함한 115개 자동 테스트 기록입니다. `temp27-silent-intrusion-build.log`와 `temp27-silent-intrusion-upload.log`는 컴파일·업로드 기록이며 `temp27-silent-intrusion-live.json`은 실제 센서·카메라·시리얼 상태 관측입니다. 기존 32°C 및 사이렌 시험 기록은 당시 정책의 이력입니다.

## 이전 변경 기록: 온도 세 구간 표시 (정책 버전 5, 2026-10-15)

| 온도 | LED / 관리자 화면 | LCD | 자동 환기 |
|---|---|---|---|
| 27°C 미만 | 초록 / 정상 | NORMAL | D9 0°·D10 저속 |
| 27°C 이상~28°C 미만 | 주황 / 주의 | CAUTION | D9 90°·D10 고속 |
| 28°C 이상 | 빨강 / 온도 위험 | DANGER | D9 90°·D10 고속 |

온도 상승·하강 모두 같은 경계값을 사용하며 새 센서값을 받으면 반영합니다. 표는 다른 경보·수동 제어·긴급 정지가 없는 경우입니다. 가스 경고는 기존 원시값 250/210 기준을 유지하고, 28°C 이상 온도 위험은 주황보다 빨강을 우선합니다. 미승인만 감지되면 기존 초록·빨강 교대와 설정 잠금을 유지하며 부저는 무음입니다. 온도 주의와 미승인이 겹치면 주황·빨강 교대, 온도 위험과 미승인이 겹치면 빨강을 유지하며 잠금은 계속 적용합니다. 환경 경고음의 낮춘 음량도 유지합니다.

관리자 화면의 세 구간과 상승·하강, 미승인 동시 발생·긴급 정지는 `artifacts/temp-bands-gui-check.log`와 합성 화면 `temp-bands-dashboard.png`로 확인합니다. `temp-bands-tests.log`는 경계값·가스 경고 유지·펌웨어 색상 판정을 포함한 118개 자동 테스트 기록입니다. 컴파일·업로드·실제 연결 관측은 각각 `temp-bands-build.log`, `temp-bands-upload.log`, `temp-bands-live.json`에 있습니다.

## 온도 자동 정지 (정책 버전 6, 2026-10-15)

현재 동작은 문서 위의 자동 제어 표를 따릅니다. `temperature-stop-tests.log`는 임계값, 냉각 대기, 수동 정지·오류 유지, 가스·미승인 동시 발생과 실제 C++ 제어 함수 검증입니다. `temperature-stop-gui-check.log`와 `temperature-stop-dashboard.png`는 합성 입력을 사용한 실제 Tk 화면 검증입니다. `temperature-stop-build.log`, `temperature-stop-upload.log`는 컴파일·업로드, `temperature-stop-serial-result.json`은 명령으로 실제 출력을 구동한 시험, `temperature-stop-live.json`은 센서·카메라 연결 관측입니다. 명령 시험은 DHT11에 실제 열을 가한 임계값 통과 시험과 구분합니다. 온도 급변의 물리 원인은 [DHT11 점검 기록](DHT11_DIAGNOSIS.md)에 별도로 남깁니다.
