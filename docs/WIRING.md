# Jetson Nano + Mega 2560 배선 안내

2026-10-14 사용자 확인 사항을 반영한 **회로 제작용 배선 계획**입니다. LCD는 **5V, I2C 4핀, 20×4**입니다. 일반 SG90은 환기구 개폐, SG90 360은 시연 장치 회전에 사용합니다. 가스 센서는 사용자가 **MQ-9**으로 확인했습니다. MQ-9 모듈의 단자·히터 회로는 실물 확인이 남아 있습니다.

**서보 전원과 시험:** 사용자가 최종적으로 **외부 5V 2A 전원** 연결을 확인했습니다. 무부하에서 한 개씩 시험하며, 외부 +5V를 Mega +5V와 합치지 않고 GND만 공통으로 연결합니다. D9의 일반 SG90은 90 → 75 → 105 → 90도 이동과 복귀를 확인했습니다. D10은 1600µs 1초 → 1500µs 1초를 세 번 반복해, RUN 동안 연속 회전하고 STOP에서 그 위치에 멈추는 것을 사용자가 확인했습니다. 운영 정지값 1500µs, 구동값 1600µs와 `ROTATION_CALIBRATED=true`를 반영했습니다. 실제 환기구의 닫힘·열림 각도와 기구 부하가 걸린 상태의 전원 여유는 별도 검증이 필요합니다.

**RGB 확인 완료:** 사용자가 모듈의 공통 −/GND와 내장 저항칩을 확인했습니다. R/G/B에 내장된 전류 제한 저항을 사용하며, 별도 330Ω 저항을 중복으로 추가하지 않습니다. 실제 빨강 → 초록 → 파랑 → 노랑 → 꺼짐 시험도 사용자 확인으로 통과했습니다. 아래 외부 저항 예시는 내장 저항이 없는 다른 RGB 부품에 해당합니다.

D10 회전 서보, RGB 색 조합, LCD 20×4, 부저 2kHz 구동 설정은 펌웨어에 반영했습니다. 실제 출력은 보정·개별 시험 후 활성화합니다. 사용자 요청으로 HW-201(IR)은 사용하지 않습니다. 부품의 좌우 핀 순서는 제품마다 달라 **인쇄된 단자 이름**으로 연결합니다.

## 1. Jetson과 Mega 연결

카메라 → Jetson USB, Jetson USB A → USB 데이터 케이블 → Mega USB B로 연결합니다. Jetson은 GPU 사람 검출을, Mega는 센서·서보·경보 제어를 담당합니다.

- Jetson은 기존 자체 전원으로 구동합니다. Mega는 Jetson의 USB에서 전원을 받습니다.
- Mega D0/RX, D1/TX에는 다른 부품을 연결하지 않습니다. 기존 USB 시리얼 속도는 115200 baud입니다.
- 이 구성은 Jetson 40핀 GPIO를 사용하지 않습니다. 센서는 Mega에 연결합니다.

## 2. 전원부터 구성

전원을 모두 뽑은 상태에서 배선합니다. 브레드보드의 두 + 레일을 각각 `MEGA +5V`, `외부 +5V`로 표시해 구분합니다. 두 + 레일은 연결하지 않습니다. GND 레일은 하나로 연결합니다. 중간에 끊어진 레일은 도통 확인 후 필요한 구간만 이어 줍니다.

| 전원 | 연결할 곳 |
|---|---|
| Mega `5V` | DHT11 VCC, LCD VCC |
| 별도 정전압 `5V` 전원 + | 두 서보의 전원 +. MH-FMD와 MQ는 각각 정격·모델 확인 후 이 전원을 사용 |
| 별도 전원 − / GND | Mega GND, 모든 부품 GND와 공통 연결 |
| HW-479 RGB LED | 공통 음극형이면 공통 −를 GND에 연결. 각 색상 핀은 저항을 거쳐 GPIO에 연결 |

**USB로 공급받는 Mega 5V와 외부 전원의 +5V를 병렬 연결하지 않습니다. 공통으로 연결하는 것은 GND입니다.** 서보 전원은 Mega 5V 핀에서 끌어오지 않습니다. VIN이나 9V 전원을 5V 부품에 연결하지 않습니다.

서보 두 개의 시동·부하 전류를 고려해 외부 전원은 **정전압 5V / 5A급을 설계 기준**으로 잡습니다. 실제 부품 전류와 배선 허용 전류를 확인해 최종 선정합니다. 5A는 공급 가능한 최대 전류이며 부품에 강제로 흘리는 전류가 아닙니다. 서보 전류는 가는 점퍼선·브레드보드 레일에 몰아 흘리지 말고 전원 분배 단자에서 각 서보로 분기합니다. 기구가 걸린 상태로 계속 구동하지 않습니다.

한쪽 전원만 켜진 상태에서 신호선으로 역급전하지 않도록 배선·탈착은 양쪽 전원을 끄고 합니다. 최종 시험 전까지 서보 외부 전원은 연결하지 않습니다.

## 3. 부품별로 꽂을 위치

**확인 대기 부품은 사진·제품 규격 확인 후 연결합니다.** 표의 VCC·GND·S·OUT 등은 물리적 왼쪽/오른쪽 순서를 뜻하지 않습니다.

| 부품 | 부품 단자 → Mega 또는 전원 | 역할·확인 사항 |
|---|---|---|
| DHT11 | DATA/S → **D2**; VCC/+ → **Mega 5V**; GND/− → **공통 GND** | 온도·습도. 4핀 단품이면 DATA–5V 사이 10kΩ 풀업, NC 미연결. 3핀 모듈은 내장 풀업 확인 |
| HW-201(IR) | **미사용, 연결하지 않음** | D3 입력·필수 센서 검사에서 제외 |
| LCD 2004A I2C | GND → **공통 GND**; VCC → **Mega 5V**; SDA → **D20/SDA**; SCL → **D21/SCL** | 5V, 4핀 I2C, 20×4. 실측 주소 `0x27`; 사용자가 온습도 글자 표시 확인 |
| 일반 SG90 | S/신호 → **D9**; 전원 + → **외부 5V**; GND → **공통 GND** | 환기구 개폐. 링크 장착 전 실제 이동 범위 확인 |
| SG90 360 | S/신호 → **D10**; 전원 + → **외부 5V**; GND → **공통 GND** | 시연 장치 회전. 1600µs 회전·1500µs 정지 확인. 본 펌웨어 전체 활성화는 가스·기구 보정 후 진행 |
| MH-FMD | S/IN/I/O → **D28**; VCC/+ → **5V 전원**; GND/− → **공통 GND** | 사용자 배선 확인. HIGH/LOW 직류에서는 무음, 1kHz·2kHz 신호에서 소리 확인. 운영은 2kHz |
| HW-479 | R → **D26**, G → **D22**, B → **D24**, 공통 − → **GND** | 사용자 확인한 내장 저항 사용. 네 색 출력과 꺼짐 시험 완료 |
| MQ-9 / FLYING FISH | AO → **A0**; DO 미사용; GND → **공통 GND**; VCC → **외부 5V** | 5V 입력의 VCC/GND/AO/DO 모듈인 경우. 히터 회로 확인 필요. 아래 측정 한계 참고 |
| 선택: 작동 허가 LED | **D30 → 330Ω → LED +**, LED − → GND | 기존 허가 표시 출력. 부품 목록에는 없는 선택 사항 |

Mega에서 D2·D3·D9·D10은 디지털 핀 줄, D20·D21은 통신 핀, D22·D24·D26·D28·D30은 끝쪽 2열 디지털 헤더의 번호를 확인합니다. **A0는 아날로그 입력 A0이며 디지털 D0가 아닙니다.** 보드를 돌려 놓아도 위치를 추측하지 말고 기판 번호를 읽습니다.

### LCD

4핀 백팩의 `GND / VCC / SDA / SCL`만 연결합니다. LCD 본체의 16핀을 따로 배선할 필요가 없습니다. Mega의 별도 SDA/SCL 헤더는 D20/D21과 같은 신호이므로 한쪽만 사용합니다. 2026-10-14 I2C 스캔에서 `0x27` 응답을 확인했고, 사용자가 실제 온습도 글자 표시도 정상임을 확인했습니다. 추후 글자가 보이지 않으면 백팩의 대비 조절 가변저항을 조절합니다.

### DHT11 풀업 저항을 브레드보드에 꽂는 방법

풀업은 **신호선과 +5V 사이에 연결하는 저항**입니다. 신호를 보내지 않을 때 DATA가 안정된 HIGH 상태를 유지하도록 합니다. DHT11에 외부 풀업이 필요한 경우 다음처럼 10kΩ 저항을 연결합니다. 저항에는 방향이 없습니다.

```text
Mega 5V ── + 전원 레일 ──┬──────── DHT11 VCC
                        │
                      [10kΩ]
                        │
Mega D2 ─────────────────┴──────── DHT11 DATA/S

Mega GND ── − 전원 레일 ────────── DHT11 GND
```

사진의 일반적인 중앙 단자 영역은 같은 번호의 A~E가 연결되고 F~J는 별도 그룹입니다. 예를 들어 **왼쪽 단자판의 비어 있는 10행**을 사용하면 다음과 같습니다. 다른 단자판의 같은 행 번호와는 별개입니다.

| 꽂을 구멍 | 연결할 선 |
|---|---|
| A10 | DHT11 DATA/S에서 온 점퍼선 |
| B10 | Mega D2에서 온 점퍼선 |
| C10 | 10kΩ 저항의 한쪽 다리 |
| 이미 5V가 공급되는 + 전원 레일 | 위 저항의 반대쪽 다리 |

A10·B10·C10은 브레드보드 내부에서 연결되므로 세 구멍 사이에 점퍼선을 더 넣을 필요가 없습니다. 저항 양쪽 다리를 모두 A10~E10 그룹에 꽂으면 저항이 우회되므로, 한쪽은 DATA 그룹, 반대쪽은 +5V 레일에 둡니다. DHT11 VCC와 GND는 각각 +5V·GND에 따로 연결합니다. 모듈의 세 핀을 모두 같은 A~E 행에 꽂지 않습니다.

사용자 사진의 DHT11은 작은 기판에 장착된 모듈형입니다. VCC–DATA 풀업이 기판에 이미 있다면 외부 저항은 추가하지 않습니다. 현재 사진만으로 내장 저항의 연결과 값을 확정하지 않았습니다. 이 예시는 외부 풀업이 필요한 경우의 연결 방법입니다.

LED용 330Ω은 다른 용도입니다. GPIO → 330Ω → LED → GND처럼 전류 경로에 직렬로 넣으며, DHT11의 DATA 풀업과 혼동하지 않습니다.

### 두 서보

일반적인 서보 배선은 갈색/검정=GND, 빨강=전원 +, 주황/노랑=신호이지만 실물 설명서와 대조합니다. 일반 SG90은 각도로 위치를 제어하고, **연속 회전형 SG90 360은 방향·속도·정지를 제어**합니다. 360도 제품에 90도 명령을 보낸다고 축을 90도 위치에 고정하는 것은 아닙니다. 실물이 연속 회전형인지 구매 규격으로 확인합니다.

환기구 닫힘·중간·열림 각도와 회전 서보의 중립 정지 펄스는 부하 없이 보정합니다. 회전형의 약 1500µs는 초기 기준일 뿐, 실제 정지값은 다를 수 있습니다. 이번 시연의 장치 차단은 회전 서보에 정지 명령을 보내는 방식입니다. 전원 자체를 끊으려면 별도 전원 차단 회로가 필요하며 현재 부품 목록에는 없습니다.

### HW-479 RGB LED

HW-479는 RGB LED 모듈로 판매되는 보드 번호입니다. 실물에 `R / G / B / −`가 있고 공통 음극형으로 확인되면 다음과 같이 연결합니다.

- Mega D26 → 330Ω → R
- Mega D22 → 330Ω → G
- Mega D24 → 330Ω → B
- 공통 GND → −

각 색상에 별도의 저항을 사용합니다. 보드에 적절한 직렬저항이 내장된 것이 확인되면 추가 저항은 생략할 수 있습니다. 공통 단자가 `+`인 공통 양극형이면 공통 단자는 Mega 5V이며 제어 극성이 반대입니다. 표시가 불명확하면 연결하지 않습니다.

정상은 초록, 경고는 빨강+초록, 위험·미승인 출입은 빨강으로 표시하도록 코드를 반영했습니다. D24는 파랑이며 경고에서는 켜지 않습니다. 사용자가 공통 −/GND와 내장 저항칩을 확인하여 `RGB_COMMON_ANODE=false`로 시험했습니다. `firmware/rgb_check`의 빨강·초록·파랑·노랑·꺼짐 순서를 실제 LED에서도 확인했습니다. 시험 뒤에는 `hardware_check`로 복구했습니다.

### MH-FMD 부저

3핀 부저 모듈은 GPIO가 S/IN 신호만 제어하고 전류는 VCC에서 공급받습니다. 부저 전원 단자를 D28에 연결하지 않습니다. 사용자가 5V·GND·D28 배선을 확인한 뒤 HIGH/LOW 직류 시험에서는 무음, 1kHz·2kHz 주파수 시험에서는 소리가 난다고 답했습니다. 시험 결과에 맞춰 운영 코드에서 `BUZZER_ACTIVE=false`, `BUZZER_DRIVE_CONFIRMED=true`를 사용하고, 경보 시 `tone(D28, 2000)`, 해제 시 `noTone(D28)`을 호출합니다. 보유 모듈의 내부 회로가 수동형이라고 확정한 것은 아니며, 확인된 구동 방식을 적용한 것입니다. 2핀 부저 단품에는 이 3핀 배선을 적용하지 않습니다.

### MQ-9 / FLYING FISH

사용자가 MQ-9으로 모델을 확인했습니다. VCC/GND/AO/DO가 있는 5V 입력 모듈이면 VCC→외부 5V, GND→공통 GND, AO→A0로 연결하고 DO는 비워 둡니다. 출력은 Mega 입력 범위 내여야 합니다. 금속 캡만 있는 6핀 센서 단품에는 이 표를 적용하지 않습니다. 보드 앞뒤 사진으로 단자와 히터 연결을 확인한 뒤 통전합니다.

MQ-9 제조사 자료는 고온 히터 5V에서 60초, 저온 히터 약 1.4–1.5V에서 90초의 주기를 명시합니다. 저온 구간은 CO, 고온 구간은 가연성 가스 감지에 사용합니다. 문서 판본에 따라 저온 전압이 다르므로 실제 제품 규격을 적용합니다. 초기 예열/안정화 조건은 48시간 이상으로 기재되어 있으며 매번 켤 때의 준비 시간과 별도로 다룹니다.

**4핀 보드에서 히터와 측정 회로가 VCC에 묶여 있으면 소프트웨어만으로 위 히터 주기를 구현할 수 없습니다.** 이번 기본 배선은 5V 고정 구동의 ADC 원시값을 확인하는 시연 범위입니다. 이를 보정된 CO 측정이나 CO ppm 표시로 사용하지 않습니다. CO 측정이 필요하면 히터 독립 구동 회로·전압 전환 드라이버·보정 절차를 별도로 설계해야 합니다. 보드 VCC 전체를 1.5V로 낮추거나 Mega GPIO로 히터를 직접 구동하지 않습니다. 구동 방식이 정해질 때까지 기존 코드의 실물 가스 감시 활성화는 보류합니다.

## 4. 회로 제작 순서

1. 전원을 모두 분리하고 Mega 5V 레일, 외부 5V 단자, 공통 GND를 구분합니다.
2. DHT11과 확인된 LCD의 배선을 먼저 완성합니다. HW-479·MH-FMD는 실물 핀·전압 확인 후 추가합니다. HW-201은 미사용입니다.
3. 두 서보의 신호선 D9/D10과 공통 GND를 배치하되 외부 전원은 아직 켜지 않습니다. 환기구 링크·회전 부하는 분리해 둡니다.
4. MQ-9은 단자·히터 회로 확인 후 배선합니다. 5V 고정 모듈의 원시값 확인과 표준 주기 구동·보정된 CO 측정을 구분합니다.
5. 완성 배선을 표와 대조한 뒤 아래 코드 변경을 반영하고 부품별로 시험합니다.

연결 후 시험 순서는 USB 통신 → DHT11 → LCD 주소·표시 → LED → 부저 → 일반 서보 → 회전 서보 → 확인된 MQ → 카메라 경보·장치 정지입니다. 전원을 끄고 부품을 하나씩 추가합니다. 센서 오류나 통신 단절 때 장치가 멈추는지, 경보 해제 후 자동 재시작하지 않는지 확인합니다.

## 5. 반영한 소프트웨어와 남은 실물 확인

제어 코드는 아래와 같이 반영했고, Mega에는 센서·LCD 전용 진단 스케치를 업로드했습니다. DHT11에서 약 26.4°C, 습도 25.7–25.8%, LCD `0x27`, A0 원시값 31–32를 처음 수신했습니다. A0 수신은 MQ-9 예열·가스 검출·보정 완료를 의미하지 않습니다.

| 항목 | 현재 상태 | 배선 후 작업 |
|---|---|---|
| 환기 서보 D9 | 위치 서보 1개 지원 | 실제 닫힘·열림 각도 보정 |
| 회전 서보 D10 | 시작·경보·오류·통신 단절과 연동한 정지/운전 펄스 구현 | 무부하 회전·정지 확인, `ROTATION_CALIBRATED=true`. 실제 부하에서 재확인 |
| RGB LED | 공통 음극·내장 저항 확인, R/G/B/노랑/꺼짐 실물 시험 통과 | 완료 |
| LCD | 20×4, 4행 화면, I2C 응답 `0x27`, 사용자 글자 표시 확인 | 완료 |
| 부저 | 1kHz·2kHz 신호에서 실제 소리 확인, 운영 코드 2kHz 반영 | 기본 구동 시험 완료, 전체 시스템 경보 연동 시험은 별도 |
| HW-201 | 사용자 요청으로 제외 | `ENABLE_IR=0`, Python `require_ir=false` 유지 |
| MQ-9 | A0 예약, 비활성 | 모듈 히터 회로·구동 방식·예열·보정과 위험/회복 기준 확정. Python 기준과 일치 |
| 실제 출력 | `WIRING_CONFIRMED=0` | 개별 시험과 배선 검증 후 활성화 |

미승인 인원 판정은 Jetson의 카메라 로직이 담당하고 Mega가 경보·회전 정지 명령을 실행합니다. 현재 출입 승인은 관리자의 임시 승인 방식이며 등록 얼굴 자동 식별은 구현되어 있지 않습니다.
