# 실제 소프트웨어 연동 점검

현재 보드는 **연속 환기 모드**입니다. [현재 실행 안내](VENTILATION.md)를 먼저 참고하세요. 아래 내용은 이전 bench 펌웨어와 짝을 이루는 점검 기록입니다.

Jetson의 기존 Tk 화면·TensorRT 사람 검출·USB 통신을 Mega의 운영 펌웨어와 연결합니다. 센서 진단 스케치 대신 `mega_controller`의 **bench 프로필**을 사용합니다. 바탕화면의 **Moble 실물 연동 점검** 또는 아래 명령으로 실행합니다.

```bash
cd '/home/moble/2.5th project'
DISPLAY=:0 bash run_integration.sh
```

화면에 `LIVE BENCH / GPU`와 점검 범위 안내가 표시됩니다. 실제 카메라·센서·출력을 사용하므로 시뮬레이션과 다릅니다. 다른 카메라 프로그램이나 IDE 시리얼 모니터는 닫습니다. 기존 사용자 계정은 dialout에 등록돼 있으며, 실행 스크립트는 필요한 경우 이 프로그램에만 새 그룹 권한을 적용합니다.

## 현재 적용 범위

| 항목 | 연동 점검 동작 |
|---|---|
| DHT11 | 실제 온습도 표시, 센서 오류 차단과 온도 경보 유지 |
| MQ-9 | ADC 원시값 표시만. 가스 보정 완료로 처리하지 않으며 가스 농도 판단·가스 경보는 적용하지 않음 |
| 카메라 | GPU 사람 검출. 미승인 인원 경보와 회전 장치 정지 |
| 출입 승인 | 운영자가 화면의 현재 1명을 30초간 승인. 얼굴 신원 인증 기능은 아님 |
| D9 일반 SG90 | 점검용 CLOSED/PARTIAL/OPEN을 75/90/105도로 제한. 실제 환기구 개폐 각도가 아님 |
| D10 연속 회전 SG90 | 1600µs 운전, 1500µs 정지. 수동 시작 후 최대 10초 |
| RGB·부저·LCD | 상태 색상, 2kHz 경보, 온습도·MQ 원시값·장치 상태 표시. 백라이트 ON |
| IR·D30 | 미사용 |

운영(production) 프로필의 가스 예열·보정 및 실제 환기구 각도 확인 조건은 유지합니다. `hardware.gas_calibrated=false`는 변경하지 않습니다. 호스트와 펌웨어의 프로필이 다르거나 MCU의 10초 제한을 확인하지 못하면 구동을 차단합니다.

## 화면에서 시험하기

1. 처음에는 **관리자 PIN 최초 설정**에서 숫자 6자리 이상을 두 번 입력합니다. 채팅으로 보내지 않습니다. 해시만 권한 600인 `config/local.json`에 저장하며 배포 ZIP에서는 제외합니다.
2. 시리얼·카메라가 정상이고 온습도·가스 원시값이 표시되는지 확인합니다.
3. 사람이 화면에 있으면 경보가 발생합니다. 운영자가 확인한 현재 1명은 **1명 승인**에서 PIN으로 임시 승인합니다. 여러 명은 한 번에 승인하지 않습니다.
4. 감시 구역이 비었으면 **경보 해제**로 경보를 해제합니다. 정상 복구에는 짧은 대기 시간이 있습니다.
5. 정상 상태에서 **10초 시험 운전**을 누르고 **처음 설정한 동일한 관리자 PIN을 한 번 더 입력**하면 D10이 최대 10초 동작합니다. 인원 승인과 장치 시작은 각각 PIN을 확인합니다. 중간에 미승인 인원·센서/통신 오류가 발생하면 즉시 차단 요청을 보냅니다. **긴급 정지**는 PIN 없이 사용할 수 있습니다.
6. 경보 해제나 일시 승인 후 자동 재시작하지 않습니다. 다시 시작하려면 시작 버튼을 다시 눌러야 합니다. 기구가 연결되지 않은 확인된 5V 전원 구성에서 점검합니다.

호스트와 MCU 모두 구동 시간을 제한합니다. 같은 RUN 요청을 반복해도 MCU 제한 시간이 연장되지 않습니다. MCU가 위험 상태나 시간 제한 때문에 OFF를 응답하면 호스트는 그 차단을 반영하고 시작 요청을 취소합니다. ACK는 실제 출력축 위치 피드백이 아닙니다.

`시작할 수 없습니다. 경보와 장치 오류를 먼저 해제해 주세요.`는 경보 또는 오류가 남았다는 뜻입니다. 한 명을 승인했더라도 카메라가 두 번째 사람을 검출하거나 승인된 사람이 화면을 벗어나면 승인이 취소됩니다. 다시 한 명만 보이게 한 뒤 승인하고 정상 운전 상태를 확인합니다. 빈 구역에서 시험할 때는 `경보 해제`로 이전 침입 경보를 해제합니다. 시작 버튼의 PIN 입력창이 뜨는 것 자체는 정상 동작입니다.

## 펌웨어 다시 준비하기

```bash
bash scripts/compile_integration.sh
sg dialout -c '.tools/arduino-cli --config-file .tools/arduino-cli.yaml upload --fqbn arduino:avr:mega --port /dev/ttyUSB0 --input-dir build/mega-integration'
# 카메라·화면을 실행하기 전, 회전 출력 OFF 상태의 통신 점검
sg dialout -c 'python3 scripts/integration_serial_check.py'
```

업로드 전 실행 중인 모니터를 종료해 포트를 비웁니다. `compile_firmware.sh`는 기본 production 설정을 빌드하므로 위 점검 빌드와 구분합니다. MCU의 startup/통신 오류 경보는 호스트 연결과 설정이 완료될 때까지 울릴 수 있습니다. 모니터가 종료되거나 통신이 끊기면 장치는 차단되고 통신 경보가 발생합니다.

호스트는 센서 보고를 받은 뒤 명령을 보내므로 부트로더가 시작되는 동안 전송하지 않습니다. MCU는 DHT11 읽기와 LCD 갱신을 모두 끝낸 뒤 센서 보고를 보내 통신과 긴 주변장치 작업이 겹칠 가능성을 줄입니다. 잘못된 패킷은 계속 차단 조건이며 실제 센서·통신 오류를 정상 상태로 숨기지 않습니다.

`logs/status.json`에는 최신 센서·출력 응답·연결 상태가, CSV에는 시간별 기록이 저장됩니다. 상태 파일에는 PIN이나 카메라 영상이 들어가지 않습니다. 물리적인 경보 소리·서보 움직임과 현장 카메라 검출 정확도는 직접 확인합니다.

## 창은 보이는데 마우스 클릭이 안 될 때

2026-10-14 실제 Jetson에서 키보드 입력과 프로그램 실행은 유지되지만 마우스 클릭이 전달되지 않는 문제가 있었습니다. Unity/Compiz 창 관리자를 재시작한 뒤 사용자가 클릭 복구를 확인했습니다. 시스템 재부팅은 하지 않았고 PIN 설정도 유지됐습니다. 같은 증상이 반복될 때는 Jetson 터미널에서 `DISPLAY=:0 compiz --replace`로 창 관리자를 교체할 수 있습니다. 잠깐 화면이 깜빡이며 이 명령을 실행한 터미널은 닫지 않습니다. 앱 자체 오류인 경우에는 `logs/monitor.log`를 별도로 확인합니다.
